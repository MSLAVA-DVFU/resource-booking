# СБР — Сервис бронирования ресурсов

Учебный frontend-проект сервиса бронирования ресурсов, разработанный на **Nuxt 4**, **Vue 3** и **TypeScript** по макету Figma. Приложение позволяет просматривать специалистов и доступные пространства, выбирать временные интервалы и оформлять демонстрационное бронирование.

**Демо:** https://mslava-dvfu.github.io/resource-booking/  
**Исходный код:** https://github.com/MSLAVA-DVFU/resource-booking  
**Макет Figma:** https://www.figma.com/design/4SzCZoQG6Qg53snFBuqrK3/Redesign?node-id=0-1

## Возможности

- **Демонстрационный вход:** переход в приложение под пользователем Иван Иванов, просмотр профиля и выход. Для входа не требуется вводить логин и пароль.
- **Каталог специалистов:** карточки с фотографиями и описаниями, поиск и сортировка по имени, просмотр информации и демонстрационное действие «Пригласить».
- **Каталог пространств:** карточки помещений с характеристиками и временными интервалами; свободные интервалы можно выбрать, занятые недоступны для выбора.
- **Бронирование:** модальное окно выбора существующего мероприятия или создания нового, указание ответственных и комментария. После успешного бронирования выбранные интервалы помечаются как занятые в текущем состоянии приложения.
- **Календарь и приглашения:** календарь в боковой панели, просмотр деталей активных приглашений и возможность их отклонить.
- **Навигация и адаптивность:** отдельная страница входа, общее оформление рабочих разделов, меню профиля и адаптация интерфейса под разные размеры экрана.
- **Обработка ошибок:** модальное окно для некорректных запросов бронирования.

> **Примечание:** раздел «Аппаратура» присутствует в навигации, но пока содержит страницу-заглушку.

## Технологии

- Nuxt 4
- Vue 3 (Composition API, `<script setup>`)
- TypeScript
- Vue Router
- CSS (адаптивная вёрстка, CSS Grid и Flexbox)
- Локальные данные TypeScript и статические ресурсы из `public/`
- GitHub Actions и GitHub Pages для публикации

## Запуск локально

**Требования:** Node.js 22 или совместимая версия, npm.

```bash
git clone https://github.com/MSLAVA-DVFU/resource-booking.git
cd resource-booking
npm ci
npm run dev
```

После запуска откройте **http://localhost:3000**.

### Команды

| Команда | Назначение |
| --- | --- |
| `npm run dev` | Запуск сервера разработки |
| `npm run build` | Production-сборка Nuxt |
| `npm run generate` | Генерация статической версии сайта |
| `npm run preview` | Локальный предпросмотр собранного приложения |

## Страницы

| Маршрут | Назначение |
| --- | --- |
| `/` | Перенаправление в каталог специалистов |
| `/login` | Демонстрационный вход |
| `/people` | Каталог специалистов |
| `/spaces` | Каталог пространств и бронирование |
| `/equipment` | Заглушка раздела аппаратуры |
| `/profile` | Профиль текущего пользователя |

Рабочие разделы защищены клиентским middleware: пользователь без демонстрационного входа перенаправляется на `/login`.

## Структура проекта

```text
app/
├── assets/css/           # Глобальные стили и CSS-переменные
├── components/
│   ├── booking/           # Календарь, приглашения, временные интервалы
│   ├── cards/             # Карточки специалистов и пространств
│   ├── layout/            # Навигация, боковая панель
│   └── modals/            # Бронирование, ошибки, базовое окно
├── composables/           # Демонстрационная авторизация, приглашения
├── data/                  # Локальные данные пользователей и ресурсов
├── layouts/               # Публичный и основной layout
├── middleware/            # Проверка демонстрационного входа
└── pages/                 # Маршруты приложения
public/                    # Изображения, иконки, шрифты
nuxt.config.ts             # Конфигурация Nuxt
```

## Ограничения демонстрационной версии

Проект разработан **без backend и базы данных**. Список специалистов, пространств, мероприятий и приглашений основан на локальных данных. Вход не проверяет учётные данные, а состояние бронирований не синхронизируется между пользователями и не сохраняется на сервере. Кнопка регистрации не реализует создание аккаунта.

## Публикация

Сайт размещён на **GitHub Pages**. Развёртывание выполняется через GitHub Actions: при отправке изменений в ветку `main` запускается генерация статического сайта и публикация полученных файлов.

```bash
git add .
git commit -m "Update project"
git push
```
